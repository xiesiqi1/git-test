############################################################
★★★ 第一件事: 量一下探头装在哪儿 ★★★
############################################################
  量【两驱动轮中心连线】到【五路探头板中心】的【前后距离】。

  仿真结论（2026-09-25，★ 已含【偏航静摩擦】）: 这个距离是"过不过得了弯"的
  【唯一决定因素】，悬崖在 2~3 cm —— 差一厘米就从"必然冲出黑线"变成"能跑"：

      探头在轮轴【后方】1 cm  → 出线（7.6 s 就脱离，丢线 45 拍）
      探头【正好在轮轴】上    → 出线（9.2 s 脱离，丢线 151 拍）
      探头【前移 0.5 cm】     → 出线（17.6 s 脱离，丢线 882 拍）
      探头【前移 1.0 cm】     → 横偏 54 mm（必然丢）
      探头【前移 1.5 cm】     → 横偏 25 mm（贴边缘，会丢）
      探头【前移 2.0 cm】     → 横偏 29 mm（会丢 —— 2 cm 就是悬崖）
      探头【前移 3.0 cm】     → 过（5.2 mm）   ← 建议装这里
      探头【前移 4.0 cm】     → 过（2.8 mm，再多无益）

  ★ 表现就是: "进弯反应慢一点，等跑出弯道了才转弯，然后直接找不到线"。
  ★ 探头在轮轴附近时，什么参数都救不回来 —— 仿真里把 Kp / KD 一路加上去、
    前视给到 40 拍，全都还是出线（见第十四节表 3）。
  ★ 所以: 距离 < 3 cm 就先【挪探头】，别调参数。挪到 3~4 cm 最舒服。
    ★★ 注意这个数字比旧版手册说的大（旧版说"1 cm 就够"）—— 那是没有偏航
       静摩擦的旧模型给的答案。真车要先克服前支撑的偏航静摩擦才转得动，
       所以机械前视必须留得更长。**按 3~4 cm 装。**

一、供电（务必共地）
  L298N 12V/VMS → 外接 7~12V 电源正极
  L298N GND     → 外接电源负极
  L298N GND     → STM32 GND          ← 必须接，否则电机乱转/不动
  L298N 5V      → 悬空（或只给传感器供电）
                  STM32 用 USB / ST-Link 3.3V 供电，不要与 L298N 的 5V 并联

二、L298N ←→ STM32 信号线
  方向（逻辑输入）：
     右电机 IN1 → PA11
     右电机 IN2 → PA12
     左电机 IN3 → PA9
     左电机 IN4 → PB3
  调速（使能/PWM，1kHz）：
     右电机 ENA → PB4   (TIM3_CH1)
     左电机 ENB → PB5   (TIM3_CH2)

三、L298N ←→ 电机
  右电机 → OUT1、OUT2   （受 IN1/IN2 + ENA 控制）
  左电机 → OUT3、OUT4   （受 IN3/IN4 + ENB 控制）

  ★ 注意：这里左右是"交叉"的，不是按 OUT1/2=左来分。依据是 safe/motor.c：
       LEFT  = IN3(PA9)/IN4(PB3)    PWM = TIM3_CH2 = PB5
       RIGHT = IN1(PA11)/IN2(PA12)  PWM = TIM3_CH1 = PB4
    电机左右接反了不要改线，把 motor.c 里 LEFT_*/RIGHT_* 两组宏对调即可。

四、编码器（测速，可选用）
  TIM2_CH1 = PA0   左轮编码器 A 相
  TIM2_CH2 = PA1   左轮编码器 B 相
  TIM4_CH1 = PB6   右轮编码器 A 相
  TIM4_CH2 = PB7   右轮编码器 B 相
  编码器 VCC → 3.3V~5V，GND → GND
  左右接反：Encoder_Init 里对调 &htim2 / &htim4 即可

五、五路循迹传感器（数字输出）
  从左到右依次接：PA3(第1路) PA4(第2路) PA5(第3路) PA6(第4路) PA7(第5路)
  全部为内部上拉输入，传感器输出开漏/推挽都可以
  ★ 安装位置见本文件开头【第一件事】—— 比接线更影响成败。

  ★ 极性（黑线对应哪种电平）—— 最容易搞反的一项
    safe/config.h 里 TRACK_ACTIVE_LEVEL_DEFAULT：
        0 = 压到黑线时模块输出【低电平】
        1 = 压到黑线时模块输出【高电平】   ← 当前值（★ 实车标定结论）
    不用重新编译也能改：停止状态下【双击 PA15】切换一次，两个轮子【一起】
    短促抖两下就是切好了；然后短按启动，看车是"追黑线"还是"躲黑线"。

    ★ 本车标定记录（2026-09-25 实测）：
        用 0 → 车【一直绕圈】，明显不对；
        改回 1 → 正常。
      所以出厂默认值是 1 —— 正常情况下【不用再按】。
      ⚠ 别再靠"压黑线时指示灯亮还是灭"去推断：模块指示灯和排针输出
        有的同相、有的反相，本项目已经因此来回改错过两次。
        这类方向问题只认上车结果（见下面 a 的判断办法）。
    不用万用表的判断办法：
      a) 短按启动后，车是【追黑线】还是【躲黑线】—— 前者说明对，后者翻一次极性。
      b) 看模块上每路自带的小指示灯。把黑线放到某个探头下，那一路的灯会变
         —— 会变说明探头是好的，剩下的只是"哪个电平算黑线"的方向问题，
         试一次就能定。
      c) 若 5 路的灯怎么放都不变 → 这是硬件问题不是代码问题：调模块上的
         灵敏度电位器、把探头调到离地 8~15mm、确认黑线够黑够宽。

    极性反了的典型现象（两种，可能只见到其中一种）：
      ① 车【几乎不理会黑线，一路直着往前冲】。
         探头离开黑线时输出的是"白"，被当成"检测到黑线"，5 路一起算出来的
         平均误差恒等于 0，车就以为没偏，一直直行。
      ② 一压到黑线就【满舵打转 / 一直绕圈】。
         白底被当成"五路全黑"，而真压到黑线时反被算成"五路全丢"，
         于是触发"丢线满舵回找"，车就在线附近原地或小半径转圈。
      ★ 2026-09-25 实测：把默认值改成 0 之后，车表现的就是②【一直绕圈】，
        改回 1 即正常 —— 所以本车的正确值是 1。

  ★ 左右顺序（"第1路"是不是真的挂在车最左边）—— 第二容易搞反的一项
    若模块【整体接反了】（排针插反、或模块转了个方向装上去），代码里的"第1路"
    实际是车上最右边那路。表现是：车追着黑线的【反方向】跑 —— 黑线偏左，车却
    向右拐，越拐越远最后冲出去。
    不用重排探头、也不用改线 —— 停止状态下【三击 PA15】翻一次"转向极性"即可。
    详见第六节（按键）和第十二节现象 D。

六、按键
  PA15 → 按键 → GND（内部上拉，按下为低电平，软件消抖 20ms）
  单击：启动 / 停止 循迹（松手后约 0.35 秒确认，这是为了和双击区分开）
  双击：切换【传感器极性】（黑线对应低电平 / 高电平）
        反馈：两个轮子【一起】短促抖两下 = 切换成功
  三击：切换【转向极性】（修正方向反过来；用于"黑线偏左车却往右拐"）
        反馈：左轮抖一下 → 右轮抖一下（和双击的动作不同，看动作就能分辨）
        三击是立即响应的，不用等 0.35 秒
  长按（≥0.8 秒）：电机自检 —— 左轮前进 1s → 停 → 右轮前进 1s → 停
      作用：不开电脑、不用串口，就能确认三件事 —— 电机接线通不通、
      左右有没有搞反（转的是不是你以为的那个轮子）、前进方向对不对。
      ★ 做自检请先把两个轮子架空（拿在手里），别放在地上。

  ★ 传感器极性和转向极性这两个开关都不需要重新编译：
      传感器极性反了 → 车不理线、一路直冲（见第五节的说明）
      转向极性反了   → 车追着线的反方向跑（见第十二节现象 D）
    两个都可能需要试，顺序是先双击定极性、再三击定转向。
  ★ 本车两个开关的标定结果已经写进出厂默认值了：
      传感器极性 = 1（黑线输出高电平）   转向极性 = (-1)
    也就是说【正常情况这两个键都不用按】—— 直接烧录就是对的。
    只有当哪天换了传感器模块 / 重接了电机线，才需要再试一遍。
  ★ 切换结果会立刻写进 Flash 保存，断电、复位、重新烧录都不会丢
    （上一版只存在内存里，一次复位就退回默认值 —— 那正是"车突然朝赛道
      对角直冲"的元凶之一）。
  ★ 反过来也成立：一旦在 config.h 里改了这两个默认值，Flash 里保存的旧
    标定会自动作废、直接采用新默认值。所以"改默认值 + 重新烧录"一定会生效，
    不会出现"改了没反应"。

七、调试口
  PA13 = SWDIO，PA14 = SWCLK      ← 保留 SWD 下载
  代码在 MX_GPIO_Init 里执行了 SWJ_NOJTAG，把 PA15(JTDI)/PB3(JTDO)/PB4(NJTRST)
  释放成了普通 IO，所以：用 SWD 下载，不要用 JTAG。

八、已占用 / 不可再用的引脚
  ★ 2026-09-28 起 OLED 占用了 5 个脚（详见第十五节）：
      PA8  = OLED_RES    PB12 = OLED_CS    PB13 = SPI2_SCK
      PB15 = SPI2_MOSI   PB14 = OLED_DC    （PB14 原本是 SPI2_MISO,
                        因为 SPI2 选了"只发主模式"，MISO 被释放出来给 DC 用）
  ★ 2026-09-29 起声光提示又占了 2 个脚（详见第十七节）：
      PB0  = BUZZER 蜂鸣器（有源模块，低电平触发）
      PC13 = LED 板载灯（低电平亮）
  PB1 PB2 PB8~PB11      → 配为模拟输入（未使用，可空）
  PA2 PA10              → 配为模拟输入（未使用，可空）
  PD0 / PD1             → ★★ HSE 8MHz 晶振脚（OSC_IN / OSC_OUT），
                          绝对不要拿去当 GPIO！见第十五节核对清单①
  PC14 / PC15           → .ioc 里标了 LSE 外部晶振（当前代码未启用 LSE/RTC）
  ⚠ PB0 是 TIM3_CH3：本工程 TIM3 只用 CH1(PB4)/CH2(PB5) 做电机 PWM，
    所以 CH3 空闲，PB0 才能当普通 GPIO。将来要改成"无源蜂鸣器"（需要方波）
    才用得上 CH3，那时 PB0 要配成定时器通道而不是 GPIO。
  PA9 已当普通输出(IN3) → USART1 不可用
  PA2 / PA3 被占用      → USART2 不可用
  => 本工程目前没有任何串口，所以"蓝牙模块 TX/RX 接 PA3/PA2"是接不了的，
     要用蓝牙需要先在 CubeMX 里给 USART 重新分配引脚（循迹传感器要挪位置）。

九、关键参数
  HSE 8MHz 晶振 → PLL x9 = SYSCLK 72MHz
  TIM3 PWM：Pre=71, Period=999 → 72MHz/72/1000 = 1kHz
  TIM2/TIM4：编码器模式，无预分频，16bit 自动回绕
  SPI2（2026-09-28 新增，给 OLED 用）：Pre=8 → 36MHz/8 = 4.5 MHz，
      Transmit Only Master（只引 SCK/MOSI，MISO 释放给 DC）
  SysTick = 1ms，控制节拍 = SysTick 分频，周期由 safe/config.h 的
  CTRL_PERIOD_MS 决定（当前 5ms = 200Hz），函数是 main.c 里的 CtrlLoop()
  控制模式：只有一种 —— 开环 PWM + 比例 + 虚拟前视差速，不用编码器。
      ★ 控制律（2026-09-25 定稿）:
                 预测误差 = 误差 + 前视拍数 × 低通后的"误差变化速度"
                 差速 = Kp × 预测误差 ÷ 2
                 差速 += 曲率积分（Q8 定点；|误差|≤1 时按 TRIM_TAU 慢慢泄漏）
      ★ 以前那个 FOLLOW_STAGE 开关（1=极简 / 2=编码器速度环 + 循迹 PID）
        已经【删除】了：编码器速度环在这条赛道上仿真零收益、还带自激风险。
        看到文档里提到它，请忽略。
      ★ 旧版的 SIMPLE_KD 已【删除】（被虚拟前视取代，原因见十三节对策 1）。
      ⚠ 但"曲率积分"是【又加回来】的，和当年删掉的那个不是一回事：
        当年删的是"速度环里的积分"；现在这个是"差速上的曲率积分"，
        专门补【偏航静摩擦】那一块，见第十三节对策 0。

十、常见"不动"的原因排查
  1) 程序卡死在 Error_Handler（表现：上电什么反应都没有，电机/屏幕全不动）：
     main.c 的 SystemClock_Config 里 HSEState 必须是 RCC_HSE_ON
     （PLL 源也是 HSE，配成 8MHz × 9 = 72MHz）。
     ★ 2026-09-28 这个坑又踩了一次，根因不在代码而在 .ioc：
       CubeMX 判断"HSE 有没有启用"看的是 PD0-OSC_IN / PD1-OSC_OUT 两个晶振脚
       在不在 .ioc 里。少了这两行，重新生成代码就会写成 HSEState=RCC_HSE_OFF，
       还会把 PD0 当空闲脚配成 Analog + 打开 PD01 重映射。
       .ioc 已修好，检查方法见第十五节的【重新生成代码后的核对清单】①。
  2) L298N 与 STM32 没共地。
  3) L298N 的 5V 跳线帽：用外部 12V 供电且要用板载 5V 输出时不要拔跳线；
     若外接 5V 直接驱动逻辑，需拔掉跳线并接 5V。
  4) 没按 PA15 按键启动（上电默认停止状态，Track_SetEnabled(0)）。
  5) 传感器极性反了 → 典型现象：车几乎不理会黑线，一路直着往前冲（误差恒为 0）。
     停止状态下双击 PA15 切一次极性即可，不用重新编译上传。
  6) 过弯冲出去 / 丢了线就找不回来 → 三种可能，先分清再动手：
     a) 探头装得太靠后（最常见）→ 先看本文件开头的【第一件事】
     b) ★ 差速跳得太猛、车一顿一顿被甩出去 → 调小 SIMPLE_DIFF_SLEW（3 → 2）
     c) 打舵量真的不够（一直贴着探头边缘被拉不回来）→ 加大 SIMPLE_KP（14 → 18）
     区分办法：停车看探头压在最外一两路 = c；压得靠中间、车却往外走 = a；
     能拉回来但过程一顿一顿/摆幅越来越大 = b。详情都见第十三节。

十一、速度 / 响应 / 反射延时 的调参指南
================================================================
【降速 / 提速】现在只有【一个】旋钮：SIMPLE_BASE_SPEED（safe/config.h）
  ★ 这一节以前列过 PWM_MAX / BASE_SPEED / SPEED_TARGET / PWM_STEP 这几个，
    那是"编码器速度环"版本的参数 —— 那套代码已经删掉了，现在【不存在】
    这些宏，照着改会编译不过。
  ★ 为什么现在"速度"就等于 SIMPLE_BASE_SPEED：控制律是开环 PWM，
    没有速度环做闭环，给多少 PWM 就是多少转速。
  想更稳/更慢 → 调小（32 → 28 → 24）
  下地起步带不动 → 调大（32 → 36 → 40 → 42），能干脆起步就停手
  ★ 速度阶梯（用当前参数重扫，见十四节表 1）：
      24 → 34.6 s    28 → 30.9 s    32 → 25.2 s ← 当前
      36 → 21.7 s    42 → 17.8 s（进 20 s）
  ⚠ 这张表比本手册的历史版本明显变慢（以前写的是 32 → 23 s、36 → 19.9 s）。
    原因有两个，都不是"这次改坏了"：
      ① 仿真模型补上了【偏航静摩擦】—— 车要花力气克服它才转得动。
         ⚠ 这个 12 PWM 的摩擦值是【反推的、不一定准】：实车反馈"力度是够的"，
         说明真车摩擦比模型假设的小，真实圈时应该更接近旧数字。
      ② ★★ 2026-09-29 把仿真里的【轮距】从 0.15 改成【实测 0.27 m】。
         轮距是"转同样的半径需要多大轮速差"的直接系数
         （转弯半径 R = 车速 × 轮距 ÷ 两轮速差），轮距大 80% 意味着
         同样的打舵量只能转出 56% 的角速度 —— 仿真的弯因此变难、更接近真车。
         旁证：实车左右轮编码器计数差 31.5%，用 0.27 m 才解释得通
         （按 0.15 m 只解释得了约 15%，当时误判成"某侧丢脉冲"）。
    **所以这张表只用来看"趋势"，绝对值以秒表为准。**
  ★★ "需要的打舵量"必须按【静摩擦】定，不能按几何公式定。
     几何公式：需要的差速 = (基础速度 − 8) × 轮距 ÷ (2 × 半径)
       轮距按实测 0.27 m 代入：
         base 24 → 4.3 PWM   base 32 → 6.5 PWM   base 42 → 9.2 PWM
     ⚠ 这个数【只是下限】：它算的是"忽略一切摩擦时，轮速差要多大"。
       真车还要先把前支撑/斜撑被横向推开的静摩擦克服掉，车才开始转。
     ★ 所以"过不了弯"的正确判据是看【弯道里的误差】：
         误差一直卡在 3~4 格（探头贴边）→ 打舵量不够

【地面反射延时的真相】
  实际滞后 ≈ 传感器自身响应(约0.1~1ms) + 地面反射建立时间 + 一个控制周期。
  软件只能压小最后一项，剩下两项只能靠"降速"和硬件改善：
    a) 传感器离地 8~15mm 最灵敏，太高反射弱、太低容易蹭地/漏光
    b) 给红外管加黑色遮光套/热缩管，隔离环境光（尤其顶灯、阳光）
    c) 模块输出端若并了滤波电容会明显加大延时 → 拆掉或换小(如 1nF)
    d) 黑线要够宽够黑、地面不要太光亮（哑光/纸面最好），
       反光地面会让阈值漂移，出现"时好时坏"
    e) 五路探头的间距决定分辨率，间距越小分辨率越高、可跑得越快
    f) 降速是唯一"零成本"的解法：速度减半，同样的滞后对应的偏差就减半

【调试建议顺序】
  1. 先用 SIMPLE_BASE_SPEED 把车降到能稳定沿线跑
  2. 上线跑，先只盯【直道】：
       直道画龙/抖  → 降 SIMPLE_KP（先）或降 SIMPLE_LEAD_TICKS（后）
       直道挺好     → 直道就别动 Kp，工夫全花在弯道
  3. 弯道过不去 → 停在弯道边上看【探头压在哪几路上】：
       压在最外侧一两路上（误差 3~4 格）= 打舵量不够
         → 加 SIMPLE_KP（14 → 18）或 SIMPLE_TRIM_KI（150 → 220）
       压得并不靠外、车却在往外滑 = 偏航静摩擦太大 / 前视不足
         → 先量探头前视（文件开头），再看要不要加大 SIMPLE_TRIM_KI、降速
     ★ 顺序别反：直道已经调好了，就别为了弯道回去动 Kp 之外的东西，
       否则等于把直道白调一遍。
  4. 稳了再提速（一次 +4），**每提一次都要回头重做第 3 步** ——
     速度越快，同样的滞后对应的横偏越大。
  5. 还想更快就动机械：探头往前挪、减小探头间距、CTRL_PERIOD_MS 调到 3~2。
================================================================
十二、先跑通寻线 —— 三步上线法
================================================================
现在的代码不用编码器。相比早期版本多了三个保护 ——
【软启动】(防"一按启动就窜出去")、【丢线爬行】(不知道线在哪时只允许低速)、
和 2026-09-25 新加的【曲率积分】(让车在弯里真正留出余量，见下面 A 组)。
控制律：预测误差 = 误差 + 前视拍数 × 低通后的"误差变化速度"，
        差速 = Kp × 预测误差 ÷ 2 ＋ 曲率积分偏置，
        基础速度会随打舵量自动下降（弯道收油）。
下面这组值已按【电赛 H 题赛道】标定（2×1.5m 直线 + 2×R0.5m 半圆），
标定过程与依据见第十四节。

【A 组】先动这一组 —— 90% 的情况改这里就够了
  SIMPLE_BASE_SPEED  32   ★唯一真正决定"能不能进 20 s"的参数。
                          ★ 当前 32：从调试值 24 提上来的那一档（2026-09-25
                            实车反馈"回到之前的速度"）。
                          ★ 这一档（轮距 0.27 m 实测、收油上限 6 之后重算）：

                          余量了。它顺带也治好了直道：静摩擦下小修正根本做不

  SIMPLE_CORNER_MIN  60   减速下限（占基础速度 %）。★ 从 75 放到 60：
                          75% 对 base 32 来说是"地板 24"，等于把收油卡死；
                          60% → 地板 19.2，才留出真正的下探空间。
                          ⚠ 有 SLOW_MAX 之后它基本碰不到了（32−6 = 26 > 19.2），
                            留着当第二道保险。
  SIMPLE_LOST_SPEED  20   ★ 2026-09-25 新增。知道往哪边找线时的速度。
                          以前这里用的是基础速度 32 —— "满舵 + 全速"结果是
                          轮胎侧滑空转，车照样直着滑出去，这就是"丢了线怎么都
                          找不回来"的原因。降到 20 后轮子抓得住地，内侧轮被
                          差速夹推到 0，车变成【原地小半径拧】。
                          还是找不回来 → 再降（20 → 16）。
  SIMPLE_LOST_BOOST_CNT 3 连续丢线几拍后开始额外加力（3 拍 = 15ms）
  SIMPLE_LOST_BOOST  10   额外加力的量（丢线时满舵量不够，必须再补）
  SIMPLE_LOST_TURN    1   丢线时朝最后偏离方向回找（0 = 直行）

【C 组】起步保护 —— 这两个是"防一启动就冲出去"的
  SIMPLE_SEARCH_SPEED 12  从没找到过黑线时允许的最大速度（爬行）
  SIMPLE_RAMP_MS     300  软启动时长：启动后输出在这段时间内从 0 线性升起

    "对误差做普通积分"，在"车想转就转"的模型里当然只有害处；现在这版是
    【Q8 定点 + 硬上限 + 主动泄漏】，专门用来补偏航静摩擦那一块，见 A 组。

     传感器极性 TRACK_ACTIVE_LEVEL_DEFAULT —— 停止时【双击 PA15】切
     转向极性   TRACK_TURN_SIGN_DEFAULT   —— 停止时【三击 PA15】切
     ★ 两个开关的正确值都已经实车标定，并写成了出厂默认值：
         传感器极性 = 1（黑线输出高电平）   转向极性 = (-1)
       也就是【正常情况下这两个键都不用按】，直接烧录就是对的。
       它们的切换都会写进 Flash 保存；而 config.h 默认值一旦被改动，
       Flash 里的旧标定会自动作废（靠"默认值签名"实现，见 safe/track.c）——
       不会出现"改了默认值重新烧录却没反应"。）

  ★ 关于"双路夹线"（黑线较宽、正常行驶时有两路探头同时压线）
    定位算法用的是【夹线定位】：取"最左被触发的路"和"最右被触发的路"的
    中点作为线的位置，误差单位是【半个探头间距】，范围 -4 ~ +4：
         -4 只有第1路              +1 第3、4路同时压线
         -3 第1、2路同时压线        +2 只有第4路
         -2 只有第2路              +3 第4、5路同时压线
         -1 第2、3路同时压线        +4 只有第5路
          0 只有第3路（五路全压也算 0）
    为什么不用"所有被触发探头取平均"：那样压住第2+3路和压住第3+4路都会算成
    0，丢掉了半格分辨率，车在线上会"不纠偏"。夹线定位能分清这两者（-1 / +1）。
    ★ SIMPLE_DEAD_BAND 现在 = 0（不设死区）：误差 ±1 那两个"居中"位置也照修，
    这样偏半格就开始纠正。代价是宽线骑在两路之间时差速会小幅抖动，
    但控制周期只有 5ms（200Hz），电机机械上跟不上，实际被平掉了，看不出来。
    若直道上真看到左右抖动 → 把 SIMPLE_DEAD_BAND 改回 1。

第 2 步：验传感器和转向 —— 单击 PA15 启动，再把黑线依次移到 5 个探头下
  期望表现（这就是"原地转向找线"，一眼看出对不对）：
    黑线在【最左】探头下 → 车向左转（左轮慢、右轮快）
    黑线在【中间】探头下 → 两轮等速，车直行
    黑线在【最右】探头下 → 车向右转

  现象 D：车朝着线的【反方向】甩（黑线偏左，车却向右拐，越拐越远）
      → 这是"转向极性反了"。停止状态下【三击 PA15】翻一次即可，
        不用重新编译下载；反馈是"左轮抖一下 → 右轮抖一下"。
      → 成因只有两个，而且现象完全一样：
        (a) 五路模块排针的左右顺序接反了（代码里的"第1路"其实是车上最右那路）；
        (b) 左右电机的接线对调了（标着 Left 的那根接了右边轮子）。
        两者都等价于"看左当成看右"，所以翻这个开关就能治好，不用改线、不用重排探头。
      → 想改开机默认值：safe/config.h 的 TRACK_TURN_SIGN_DEFAULT。
        本车实车标定的正确值是 (-1)（也就是现在的出厂默认值）—— 2026-09-25
        实测：用 (+1) 时车往黑线的【反方向】拐，改成 (-1) 才对。正常情况
        【不需要】动这个开关；只有换了车、或重接了线才需要重新试一次。
        顺便记住：这个值只能【上车试】，不能靠推理 —— 代码里那套映射
        （err>0 → 左轮快 → 车向右追线）本身是自洽的，公式推导永远是对的，
        反了只可能是硬件接线与代码假设不一致（本项目已因此来回错过几次）。
  现象 E：车几乎不理会黑线，一路直着往前冲（想压线也压不住）
      → 这是【传感器极性】反了的典型样子：探头看到"白"被当成看到"黑"，
        5 路一起算出来的误差恒为 0，车就当自己没偏
      → 停止状态下双击 PA15 切一次极性，不用重新编译下载
  现象 E'：一压到黑线就【满舵打转 / 一直绕圈】，可在白底上却能直着走
      → 同样是【传感器极性】反了：白底算成"五路全黑"、压线反而算成"五路全丢"，
        于是触发丢线满舵回找，车就在线附近原地或小半径转圈。
        它和现象 E 是一回事的两种表现，处理办法一样：双击 PA15 切一次极性。
      → ★ 本车 2026-09-25 实测到的就是这一种（默认值改成 0 后一直绕圈，
        改回 1 就正常）。所以出厂默认值 = 1，正常情况【不用按这个键】。
  现象 F：线放到探头下完全没反应，模块上的灯也不变
      → 硬件问题：调模块的灵敏度电位器 / 探头离地 8~15mm / 黑线够黑够宽
  现象 G：只有某一路没反应
      → 那一路线虚接或探头坏了，先换一路试

  ★ 顺序很重要：先双击 PA15 把【传感器极性】定下来（现象 E），
    再三击 PA15 把【转向极性】定下来（现象 D）。
    极性不对的时候整个逻辑都是反的，转向根本没法判断。
  ★ 另外每次切换后 Track_Init() 会复位内部状态，所以切完直接短按启动就行。

第 3 步：放地上跑 —— 先解决"带不动"，再只管一个参数
  【带不动 / 起步不动】按可能性从大到小排查：

       ★★ 4') 两个弯打舵量不一样（例如 弯1 内0外60 / 弯2 内15外40）→

                                   OLED 的 E 那一行，看"偏出去"的那个弯是不是
                                   误差打到 ±3~±4。是 → 加 SIMPLE_LEAD_TICKS

                                   去强行统一，见第十三节对策 1。
    5) 每次修正都"一顿"、车往外甩（差速过大，但随后能拉回来）→

================================================================
十三、弯道冲出黑线 / 反应慢 怎么办
================================================================
【先讲原因 —— 弯道过不去其实有【三个】完全不同的根因，别混在一起治】
  根因 A：事后感知 + 探头装得太靠后
    五路探头是"低头看脚底下"，只能看到车前一小片。于是：
      直道上 → 线一直在探头下面 → 看得见，不会偏
      进弯道 → 黑线往一边拐出去了，探头要等车【已经偏出去】才"看见"
    → 等它看见，车已经在弯里了。
    典型症状：**进弯反应慢，等跑出弯道了才转弯，然后直接找不到线。**
    ★ 这个问题的正解首先是【物理】的：探头往前挪（文件开头第一件事）。
      仿真：探头从"轮轴正上方"往前挪 3 cm，最大横偏从"出线"变成 8 mm。
  根因 B：打舵量不够克服"偏航静摩擦"（2026-09-25 查清，但【被实车收窄】了）
    典型症状：**车头能转，但整条弯都贴着探头边缘往外蹭，压不回到中间；
    误差全程卡在 3~4 格（最外侧一两路）。**
    为什么：弯道几何上需要的差速很小（R=0.5m 只要 3.6 PWM），纯比例控制给出的
    打舵量也就很小；但车要先克服前支撑被横向拖动的静摩擦才转得动。
    ★ 更根本的是：这个"到底需要多少"的信息【不在传感器信号里】。五路数字
      探头在 1.8cm 线上，"正中"的窄带只有约 1mm 宽，所以车实际稳定停在
      err=±1 —— 直道 ±1，弯道也是 ±1。实测(仿真)：直道误差"同侧连续"最长
      828 拍，弯道 822 拍，【完全分不开】。于是纯 P 只能靠"车偏出去 → 误差
      变大 → 催出打舵量"跟弯。
    ⚠⚠ 重要修正（2026-09-25 实车）：根因 B 这条【被用错了】。用户报的是
      "车头转过来了、车身往外滑"，我据此断定是 B，把 Kp 从 8 加到 14。
      结果实车反馈是"力度是够的，是左右差速过大，偏离赛道了" —— 也就是
      根因 C。**"车头转过来、车身往外滑"这句话，B 和 C 都能解释**：
        B：力量不足以把车身推正      → 车被"甩"到外侧，且回不来
        C：一次打得太猛把车头甩过头  → 车被"甩"到外侧，但随后能反向拉回来
      所以先别急着归因，按下面的区分办法做。
  根因 C：★ 打舵量【变化太猛】（2026-09-25 实车反馈，新增）
    典型症状：**"每次左右调速时左右差速过大，偏离赛道了"** —— 车不是转不动，
    而是每次修正都像"一顿"，车头被猛地拧一下，甩出去；能看出它在反复纠正，
    但摆幅越来越大，最后出线。
    为什么：误差从 +2 跳到 -2 时，差速在【一拍(5ms)之内】就从 +14 变到 -14。
    电机机械时间常数 30~50ms 根本跟不上 —— 车拿到的是一个"阶跃"指令：
      先猛地一拧 → 车头甩过去 → 等传感器看回来已经转过头 → 再反向猛拧 → …
    再加上 SIMPLE_DIFF_MAX 限的是【单侧】量，两轮实际差速可到 2×32 = 64 PWM，
    而 R=0.5m 在 base32 下只需要约 7.2 PWM（差了近 9 倍）—— 上限给得太宽，
    让它"猛"得起来。
    ★ 正解是【对策 0.5】，见下：加"差速变化率限幅"，把"跳"改成"爬"。
  ★★ 怎么区分（按这个顺序排除）：
     ① 先跑"停在弯里"的测试：车停稳时看探头压在哪几路。
          压在最外侧一两路（误差 3~4 格）→ 根因 B → 走【对策 0】
          压得并不靠外、车却仍往外走 → 继续看 ②
     ② 看偏出去之后能不能被拉回来：
          能拉回来，只是过程一顿一顿 / 摆幅越来越大 → 根因 C → 走【对策 0.5】
          拉不回来，一直贴着边缘往外蹭           → 根因 B → 走【对策 0】
     ③ 如果"还没进弯就开始减速、或者等出了弯才转" → 那是根因 A（前视问题），
       走【对策 1】，和上面两个都不冲突。

【对策 0 —— 打舵量要够大：SIMPLE_KP + 曲率积分】★ 新增，专治根因 B
  两件事一起做，缺一不可：
  ① SIMPLE_KP 14（2026-09-25 从 8 回到 14）
     Kp 决定"偏一格给多少打舵量"。弯中误差 2 格时：Kp=8 只给 8 PWM，
     Kp=14 给 14 PWM —— 后者才推得动偏航静摩擦。
     仿真：Kp=8 → 弯中 |误差| 平均 3.52 格（贴边，再偏一点就没线）；
           Kp=14 → 1.13 格（有余量了）。
  ② 曲率积分 SIMPLE_TRIM_KI=150 / _LIMIT=16 / _TAU=50
     它把"误差持续偏向同一侧"这个稳态偏置【自己学出来】：误差偏一格时每拍
     涨 0.15 PWM，约 0.5 秒攒够 15 PWM。于是误差能回到 0，而差速仍然维持着
     —— 弯中就有了真正的余量。误差回到线上(±1 以内)后，它按 50 拍(250ms)
     的时间常数泄漏掉，所以出弯后不会把车带偏。
     ★ 它顺带治好了直道：偏航静摩擦下小修正根本做不出来（打舵量不够），
       有了这个偏置才能做细微调整 —— 仿真里直道横偏从 19mm 降到 1~8mm。
     ★ 所以"加大 Kp"和"加积分"在这里【不冲突】：Kp 管即时反应，积分管稳态
       偏置；两个都加上余量更大。仿真：Kp=24 + 积分时弯中 |误差| 只有
       0.90 格、直道横偏 1.0 mm。
  怎么调：弯中还是贴边          → Kp 14 → 18 → 24（或积分 150 → 220）
          直道开始画龙          → Kp 回到 12 → 10
          直道缓慢地大幅来回摆  → 积分调小（150 → 100）或上限调小（16 → 12）
          出弯后车往一边偏一下  → 泄漏调快（TAU 50 → 30）
  ★ 注意：这一招和早期"过弯不要动 Kp"的建议是【反的】。那条是"Kp=8 +
    没有积分"的年代写的，针对的是根因 A。判据永远是看探头压在哪一路上。
  ⚠⚠ 前提是【先排除根因 C】。如果车是"一顿一顿地甩出去"，加 Kp 只会甩得更凶
     —— 因为 C 的毛病就是"打舵量变化太猛"，而加 Kp 等于把变化放大。

【对策 0.5 —— ★ 差速变化率限幅：SIMPLE_DIFF_SLEW】★★ 新增，专治根因 C
  这是 2026-09-25 实车反馈"力度是够的，是每次左右调速时左右差速过大，
  偏离赛道了"之后加的。它和上面所有对策都不冲突，而且是【纯赚】的：
  加它之后仿真里的一圈用时、最大横偏基本不变（23.01 → 23.02 s），
  但单拍差速跳变从 14 PWM 降到 3 PWM。
  ① SIMPLE_DIFF_SLEW = 3（PWM/控制拍，5ms）
     含义：差速每拍最多变 3 PWM。从 0 到满舵要爬约 55ms —— 和电机机械时间
     常数（30~50ms）同量级，所以车"跟得上"，不会再有阶跃。
     ★★ 关键性质：它【不降低任何上限】。持续偏一侧时差速照样能爬到满舵，
       所以不会削弱"克服静摩擦需要的力气"—— 这正是它比"直接降 Kp"安全的地方。
     取值依据（仿真扫出来的平台）：1 太慢，会把车拖到跑丢；2~6 都可用；3 在
     "偏航摩擦从 0 到 12 PWM"的整个范围内都不会让结果变差。
  ② 如果还甩，再依次动（一次一个）：
     · SIMPLE_DIFF_MAX 32 → 24 → 20   （收窄"最大能有多猛"）
     · SIMPLE_KP 14 → 10              （降低"每格误差换多少舵"）
     · 同时把 SIMPLE_LEAD_TICKS 30 → 36 补回响应（限幅会让响应略慢）
  ③ 副作用（必须知道）：限幅让响应略微变慢，所以【传感器噪声大】的场地上
     横偏会大一点（仿真：误判 3% 时前视 0 拍的横偏从 12.5 变 21.3 mm）。
     补偿办法就是把前视从 20 提到 30（同一个噪声下反而回到 10.9 mm，
     无噪声时更是从 8.5 mm 降到 2.4 mm）。**"限幅"和"前视"要一起调。**
     ★ 2026-09-29：20 → 30 这一档【已经并进默认值】了（见 B 组参数表），
       所以现在再补响应是 30 → 36。
  ④ 什么时候【别】用它：如果你的车是"力度真不够、转不动"（根因 B），
     把 DIFF_SLEW 调小只会让车更转不动。先按上面的 ①②③ 区分清楚再动手。

【对策 1 —— 虚拟前视：SIMPLE_LEAD_TICKS / SIMPLE_LEAD_TAU】（治根因 A）
  ★ 它取代了旧版的 SIMPLE_KD。先说旧版为什么不行：
    旧 KD = "本拍误差 − 上一拍误差"，数字探头是"一格格跳"的，所以这个差值
    只在那一拍(5ms)出现一次。而电机+齿轮箱的机械时间常数约 30~50 ms ——
    5 ms 的指令还没等轮子转起来就没了。仿真把 KD 从 8 加到 16、24，
    在"探头前视不足"的场景里【一次都没救回来】（表 3）。
  ★ 现在的做法：把"误差变化速度"先【低通】(时间常数 LEAD_TAU=20 拍=100ms)，
    再往外推 LEAD_TICKS=30 拍，得到"预测误差"，用它算差速。
    低通把它摊成持续约 100 ms 的指令 → 电机跟得上；
    外推等效于把探头虚拟地往前挪约 3.9 cm → 刚进弯就压舵。
  ★ 直道上误差不变 → 低通后的变化速度≈0 → 预测误差=误差 → 直道手感完全不变。
    这就是它比"直接加大 Kp"高明的地方。

  ★★ 【2026-09-29 实车新案例：两个弯打舵量不一样，也是靠它治】
     现象（用户原话）："第一个转弯是内轮0、外轮60；第二个弯道内轮15左右、
     外轮40左右。" 同一个半径的弯，打舵量差了 2.4 倍。
     反推（纯代数，不依赖任何模型）：输出是
         内轮 = 基础速度 − 差速,   外轮 = 基础速度 + 差速
     而基础速度又随差速自动收油 50%，所以
         内轮 = 32 − 1.5 × 差速
     差速到 21.3 时内轮算成负数 → 被第 7 步的"平移夹"抬到 0，
     同时外轮被推成 2 × 差速 = 60。反推得弯1 的差速确实到了 30；
     弯2 不饱和，差速 ≈ 12.5（内15 外40 正好对上）。
     ⚠ 关键推论：差速要 30，只有"预测误差 ≈ 4 格"才凑得出，也就是
       【车在弯里贴到最外侧那一路了】。所以因果是
         先偏出去 → 控制器拼命补 → 打满舵
       而不是"舵打太猛把车甩出去"。
     处方：加大前视（20 → 30）。仿真验证（只改这一项）：
         最大横偏 8.5 → 2.4 mm，两个弯的误差都稳在 1.0，
         打舵饱和率 4% → 0%，一圈 25.9 → 26.1 s（几乎不变）
       —— 差速不是被砍小的，是"车不偏出去了，两个弯自然落到同一档"。
     ⛔ 反面做法（试过、被仿真否掉）：把 SIMPLE_DIFF_MAX 从 32 砍到 13，
        两个弯确实会变成完全一样（都是 内16 外42），但那是"强行统一"——
        纠偏能力同时被砍掉：弯里误差 1.0 → 4.0、最大横偏 8.5 → 40.8 mm
        （探头半跨只有 20 mm，超了就是丢线），摩擦假设偏大时直接出线。
     验证脚本：tools/sim_turn_unify.py（把每个弯的内轮/外轮 PWM 逐拍抓出来，
     直接回答"两个弯统一了吗"）。

  怎么调：进弯还是慢        → 加大 SIMPLE_LEAD_TICKS（30 → 36 → 40）★ 别超 40
          直道出现细碎抖动  → 调小 SIMPLE_LEAD_TICKS（30 → 20 → 12），
                              或加大 SIMPLE_LEAD_TAU（20 → 30，更钝）

【对策 2 —— 弯道自动减速：SIMPLE_CORNER_SLOW / SIMPLE_CORNER_MIN】
  打舵量越大，基础速度自动降得越多，下限由 SIMPLE_CORNER_MIN 控制（当前 60%）。
  为什么有效：转弯半径和速度是【平方】关系，降 20% 的速度能换来约 50% 的转弯能力。
  ★★ 2026-09-25 修正了这里以前的一个错误结论。原话是"H 题是缓弯，减速没有收益、
     纯吃时间，所以只用 15% 当保险"。它错在两处：
       ① 它来自仿真（理想模型、没有打滑），必然低估收油的收益；
       ② 15% 在 base 24 时算下来只降 2.4 PWM —— 本来就是个"名义上存在"的值。
     提速到 32 之后它的恶果就暴露了：**看到弯却收不油，直接冲出去**。
  ★ 加虚拟前视之后它的时机也顺带对了：收油量 ∝ 打舵量，而打舵量现在含有
     前视项，于是"误差一开始变化就收油"，补上了以前"进弯第一拍收得最少"的毛病。
  怎么调：弯道冲出去 → 加大（50 → 60 → 70）
          弯道慢得它自己都过不去 → 改小（50 → 40）
  ★ 下限别乱放：floor = 60% × 基础速度，base 32 时是 19.2 PWM，
    离电机死区(8)不远了，再往下放弯道上反而"带不动"。

【对策 2b —— ★★ 弯道"明显减速"：SIMPLE_CORNER_SLOW_MAX】2026-09-29 新增
  【实车原话】"车跑到后面的转弯时，明显减速。"
  【为什么以前没治住】收油量 = |diff| × 50%，而 diff 里含有【曲率积分】
    (s_trim_q)。积分在持续弯道里会顶到 SIMPLE_TRIM_LIMIT(16 PWM)，
    而且【它在弯里不泄漏】—— 泄漏条件是 |误差| ≤ 1，可弯道里误差通常 >1。
    于是弯道中后段的收油被叠加到最大值，base 一路被压到底：
        直道 32 → 弯道中位 24 → 最深 19（正好撞上 CORNER_MIN 地板 19.2）
    也就是弯道里有一大半时间车是以"直道 60~75% 的速度"在爬。
  【★ 怎么验证（10 秒，不用下地）】看屏上第 3 行 B 和第 4 行 L：
      直道 B 应该 32（或接近）；一进弯 B 掉到 20~25 就是收油过深；
      再看 L —— 如果出现 0 或很小的值，说明内侧轮已经被夹停了。
    ⚠ 别和"丢线降速"搞混：丢线时第 2 行 LOST 会 >0，那是另一回事（对策 3）。
  【怎么改】加大 SIMPLE_CORNER_SLOW_MAX（默认 6 → 8 → 10）。
    ★ 先动上限、不要先降 SIMPLE_CORNER_SLOW：上限只管"最多收多少"，
      原来那套"打舵越大收得越多"的曲线完全保留，改动最小、最不容易改坏。
  【仿真依据（轮距改用实测 0.27 m）】
      方案                 直道 base   弯道 base(中位/最深)   一圈     最大横偏
      现状（无上限）          31          24 / 19            27.38 s   8.6 mm
      只加上限 6              32          26 / 26            25.21 s   5.2 mm ★推荐
      上限 6 + SLOW 降到 35   32          26 / 26            25.03 s   6.6 mm
      上限 8 + SLOW 降到 25   32          27 / 27            24.50 s   7.1 mm
      上限 8 + SLOW 降到 30   32          26 / 24            24.28 s  11.9 mm ← 横偏偏大
    → 只加上限 6 这一项：弯道【最慢的瞬间】从 19 提到 26（+37%），圈时快 2.2 s，
      横偏反而从 8.6 降到 5.2 mm（车不再被夹到地板）。
    ⚠ 想更快就再降 SLOW，但横偏会跟着涨；噪声 3% 时 25 那档会到 18.3 mm，
      已经贴着探头半跨 20 mm（= 丢线）。**一次只降一档，跑一圈再决定。**
  【★ 为什么你觉得是"后面的"那个弯更明显？（诚实说：仿真里没有复现）】
    仿真里 BC / DA 两个弯的 base 完全一样（都是 24），因为模型里直道足够长、
    积分被漏干净了。真车更可能是：直道上车在轻微画龙 → |误差| 常常 >1 →
    积分【漏不干净】 → 第二个弯是"带着上次的残留积分"进的，diff 更大 → 收油更多。
    这个解释与"里程/电池"无关，而且加上限之后它自然被压住。
    ⚠ 但如果加了 SLOW_MAX 还是"后面明显慢"，就要查另外两条：
       ① 第 2 行 LOST 有没有数（丢线回找，每次都要重来）；
       ② 第 6 行 ENC 后半圈涨得是不是明显变慢（电机发热/电池掉压）。

【对策 3 —— 丢线后"降速 + 加力"：SIMPLE_LOST_SPEED / _BOOST / _CNT】
  ★ 这里原来有两个真问题：
    ① 丢线时用的"满舵"是什么？是"误差 = 4"。而"最外侧探头刚好压到线"也是
       误差 4 —— 两者算出来的差速【完全是同一个值】。也就是说车冲出黑线那
       一刻，控制量压根没变，白白浪费了"丢线"这个严重信号。
       → 现在连续丢线 3 拍后（15 ms）额外加一刀（SIMPLE_LOST_BOOST）。
    ② 丢线期间用的还是【基础速度】。满舵 + 全速 = 轮胎侧滑空转，车照样直着
       滑出去，怎么都找不回来。
       → 2026-09-25 新增 SIMPLE_LOST_SPEED = 20：降速后轮子抓得住地，
         内侧轮被差速夹推到 0，车变成【原地小半径拧】。
  怎么调：丢了线就抓不回来   → 先降 SIMPLE_LOST_SPEED（20 → 16），
                               再加大 SIMPLE_LOST_BOOST（10 → 16 → 22）
          偶尔误触发甩一下   → 加大 SIMPLE_LOST_BOOST_CNT（3 → 5 → 8）

  ★ 第 7、8 行：丢线时积分被清零（那时误差是"满舵"这个人为值，积它没意义），

  ★ 关键词是"立刻"：如果"停一下才反应"，加大 SIMPLE_LEAD_TICKS。

    ——如果车"提前"就开始纠正方向，说明前视在工作。

【如果对策 0~3 都上了还是冲出去，按这个顺序查】
  0) ★★★ 探头位置 —— 先量！这是唯一"半厘米定生死"的因素（见文件开头）。
     仿真里把 Kp / 差速上限全加到最大，都救不回"探头在轮轴上"这种装法。
  1) 降速 —— SIMPLE_BASE_SPEED 从 32 降到 28 试试，
     但注意【降速会直接吃掉一圈的时间】，H 题要 20 s 内跑完，
     所以先确认是不是真的必须降（见第十四节的排查顺序）。
  2) 探头离地高度 —— 8~15mm 最灵敏（见第十一节 d）。
  3) 探头间距 / 只有 5 路 —— 物理分辨率就到这儿了，间距越小越好。
  4) 地面反光造成瞬时误判 —— 见第五节。
  5) 检查机械：前支撑是不是"拖"着的（斜撑磨地、万向轮卡死）——
     这正是仿真里要给 12 PWM 的"偏航静摩擦"。前支撑越顺，车越好转。
  6) 确实想跑快 —— 那就该上编码器做闭环 + 按赛道里程做前馈了
     （见第十二节末尾"什么时候该上编码器"）。

【题目参数（2026 全国大学生电子设计竞赛 H 题 车载平衡滚球运动控制系统）】
  跑道     两段 1.5 m 直线（AB、CD）+ 两个半径 0.5 m 的半圆弧（BC、DA）
  黑线宽   1.8 ± 0.2 cm
  周长     2×1.5 + 2×π×0.5 ≈ 6.14 m
  硬指标   从 A 点出发绕一圈停回 A：≤ 20 s，停车偏差 ≤ 2 cm
           （另有"通过 B 点 ≤ 8 s"、"一圈 ≤ 30 s"等分项要求）
  小车     长宽 ≤ 35 cm × 25 cm，轮式驱动、车载电池

  ★ 由"周长 6.14 m ÷ 20 s"立刻得到一个必须背下来的数：
        平均速度 ≥ 0.31 m/s
    换成直线段更好用：**1.5 m 直线要在 4.8 s 内跑完**。
    这就是速度标定基准 —— 秒表量一次直线段就够了（见下面第 ⑤ 步）。

  ★ 还有一条容易被忽略的规则：「投影完全脱离轨迹线，则该次测试失败」。
    而五路探头的半跨只有约 ±20 mm —— 也就是横向偏移不许超过 2 cm。
    仿真里最大横偏 1.0 mm，留了 20 倍余量；但真车上如果打滑、噪声大，
    这个余量会变小，这也是"不能一味提速"的原因。

【① 先算一下这个赛道到底需要多大的打舵量】
  一个通用公式（差速单位 PWM，基础速度单位 PWM，轮距和半径单位 m）：
        需要的差速 = (基础速度 − 电机死区) × 轮距 ÷ (2 × 圆弧半径)
  怎么来的：差速决定角速度 ω = (v右 − v左) ÷ 轮距。因为差速是"一侧加、
            另一侧减"，所以左右轮速差是差速的 2 倍（2 × 差速），于是
            ω = 2 × 每 PWM 转速 × 差速 ÷ 轮距。沿半径 R 的弧走需要 ω = 速度 ÷ R。
            又因为低于死区的 PWM 轮子根本不转，"有效速度"是 (PWM − 死区)。
            联立即得上式 —— 分母那个 2 别丢。
  ★ 电机死区按 8 PWM 取（低于它轮子不转）。
  ★★ 轮距 = 【实测 0.27 m】（2026-09-29 用户确认；以前按 0.15 估，偏小一半）。
     轮距直接进公式的分子，估错会让结论整体偏小 —— 下表已按 0.27 重算。
     代入 H 题（轮距 0.27 m、R = 0.5 m）：
        基础速度 24 → 需要 4.3 PWM
        基础速度 32 → 需要 6.5 PWM    ← 当前
        基础速度 42 → 需要 9.2 PWM    （H 题目标）
  ★ 这个公式算的是"忽略一切摩擦时，轮速差要多大"—— 所以它【只是下限】，
    不能直接拿来判"力度够不够"。
    ⚠ 本手册在这里【连错过两次】，两次都是"拿一个数字当判据"：
      第一次：写"需要的打舵量非常小 → 过不了弯九成不是力度不够" → 于是把
              Kp 从 14 收到 8。这直接造成了后来说的"转不过去"。
      第二次（2026-09-25）：把上面那句推翻，改口说"真因是偏航静摩擦、力度
              不够" → 又把 Kp 加回 14。结果实车反馈是"力度是够的，是差速
              过大、偏离赛道了"。
      两次的毛病是同一个：**拿一个"应该需要多少"的数字，去替代"实车到底怎样"
      的观察。数字只能圈定范围，不能替你下诊断。**
  ★★ 那 3.6 PWM 这个数字到底该怎么用？—— 用它查【差速上限是不是给得太宽】：
        R = 0.5 m、base 32 时，两轮真正需要的速度差 ≈ 7.2 PWM
          （= 2 × 3.6；因为 SIMPLE_DIFF_MAX 限的是【单侧】量，两轮差是它的 2 倍）
        而代码里 SIMPLE_DIFF_MAX = 32 → 两轮差可达 64 PWM
        → 上限是"需要量"的【约 9 倍】。
        这就是"差速过大"能发生的物理原因：上限太宽，让"猛舵"成为可能。
        但对策【不是把上限一刀砍掉】（那会伤到"真需要大力"的场合，仿真里
        YAW_DEAD=12 时把上限收到 20 会把一圈从 25.9 s 拖到 28.1 s），
        而是加 SIMPLE_DIFF_SLEW 限制"差速每拍能变多少"—— 见第十三节【对策 0.5】。
  ★ 判断实车到底缺什么，只有两个可靠办法（别再用算式代替观察）：
     ① 停在弯里，看探头压在哪一路上：
         压在最外侧一两路（误差 3~4 格） = 力度不够 → 加 Kp / 加积分
         压得并不靠外、车却往外走       = 前视不足 / 速度过高 / 打舵太猛
     ② 看偏出去之后能不能被拉回来：
         能拉回来，但一顿一顿 / 摆幅越来越大 = 打舵太猛 → 调小 DIFF_SLEW
         拉不回来、一直贴着边缘往外蹭       = 力度不够 → 加 Kp / 加积分

【③ 仿真（理想模型）和真车的差别 —— 必须知道，否则会误判】
  仿真里基础速度一路加到 46（约 0.4 m/s），一圈 16.6 s，最大横偏也只有 14.9 mm。
  也就是说【理想情况下 20 s 有很大余量】。但真车的限制不在几何，而在：
    · 电机启动/换向的过渡过程      （已补进模型：TAU_MOTOR ≈ 45 ms）
    · 传感器误判与地面反射延时      （已补进模型：NOISE，且会被前视放大）
    · ★ 探头的物理安装位置          （模型里是假设值，必须自己量！且要 ≥3 cm）
    · ★ 前支撑/斜撑的偏航静摩擦      （已补进模型：YAW_DEAD = 12 PWM，是未知量）
    · ★★ 横向打滑（"差速大了就往外甩"）（模型里【没有】！见下）
    · 左右电机不一致、电池电压下沉  （模型里没有）
  所以：**仿真只用来定方向和量级，最终能跑多快必须实车实测**。

  ⚠⚠ 最重要的一条：**这个仿真对"差速给得大不大"几乎不敏感。**
    把 YAW_DEAD 设成 0（也就是"力度完全够"的世界）之后，Kp 从 4 扫到 14、
    差速上限从 8 扫到 32，仿真给出的最大横偏【全都是 1 mm 左右，全都没事】。
    因为模型里的转向是纯几何的：差速大就转得多，不会有任何代价。
    而真车不是 —— 差速一大，轮胎/前支撑就开始横向打滑，车就被甩出去了。
    所以"差速过大"这一类问题，**仿真帮不上忙**（它看不到副作用）。
    能用的只有这个算术：
        真正需要的【两轮速度差】= 基础速度对应的速度 × 轮距 ÷ 半径
        以 base 32(≈0.28 m/s)、轮距 0.27 m(实测)、R 0.5 m 代入 → 约 13 PWM
        （轮距按 0.15 估时是 7.2 PWM —— 轮距一实测，需要的量就翻了近一倍）
        而代码里 SIMPLE_DIFF_MAX=32 限的是【单侧】量, 两轮实际差速可到 64 PWM。
        → 上限仍是"需要量的 5 倍"，所以"差速过大"依然可能发生，
          但余量比原来以为的（9 倍）小一半 —— 这也解释了为什么实车
          抱怨的是"差速过大"而不是"力度不够"。
    结论：**这类问题只能靠"改一处、跑一圈、看结果"，不要指望仿真给答案。**
    （2026-09-25 这条是被实车打脸之后才写下的：仿真说"怎么调都完美"，实车说
      "差速过大甩出去了"。）

  ★ 另外：仿真里"横偏 8 mm"这种数字，是在【模型含偏航静摩擦】之后才出现的；
    旧版本仿真给过"横偏 1 mm、弯道完美"—— 那个 1 mm 现在是"力度足够"情形下的

【④ 针对 H 题的操作顺序】
  第 0 步：★ 量探头前视距离（两驱动轮中心连线 → 探头板中心）。< 3 cm 就挪到
           3~4 cm。这一步排在所有调参前面，软件补不回来。
  第 1 步：两个轮子架空，长按 PA15 做电机自检（第六节），确认左右/方向
  第 2 步：单击启动，用黑线纸在 5 个探头下移动，确认是"追线"不是"躲线"
           （不追 → 停止状态下双击 PA15 切传感器极性；仍不对 → 三击切转向极性）
  第 3 步：上赛道跑一圈，看 OLED 第 1 行计时。这是唯一的验收手段。
     ★ 计时不用秒表了：第 1 行 RUN T12.3 L11.8（T = 这一圈 / L = 上一圈），
       短按启动自动归零开跑，短按停止冻结。见第十五节。
     · 一圈 > 20 s     → 只加 SIMPLE_BASE_SPEED，每次 +4
                          （32 → 36 → 40 → 42，H 题参考目标约 42）
     · 一圈 ≤ 18 s     → 余量够了，开始磨稳定性
     · 直道就画龙      → SIMPLE_KP 调小（14 → 10 → 8）；
                          还摆再调小 SIMPLE_LEAD_TICKS（30 → 20 → 12）；
                          场地噪声大也把前视收到 20~12
     · 进弯迟钝（在弯口才发现要转、等出了弯才转）→
                          SIMPLE_LEAD_TICKS 调大（30 → 36）★ 别超 40
     · ★★★ "两个弯的打舵量不一样"（例：弯1 内0外60 / 弯2 内15外40）→
                          先看 OLED 的 E 那一行：偏出去的那个弯误差是不是
                          打到 ±3~±4 了? 是 → 同属"进弯太晚"，加
                          SIMPLE_LEAD_TICKS（30 → 36 → 40）。
                          ⛔ 不要用"砍 SIMPLE_DIFF_MAX"去强行统一（见十三节对策 1）
     · ★★★ 车"一顿一顿地甩、每次左右调速时差速过大、然后偏离赛道"→
                          这是【差速变化太猛】，按这个顺序：
                            ① SIMPLE_DIFF_SLEW  3 → 2   （让差速爬得更慢）
                            ② 还甩 → SIMPLE_DIFF_MAX 32 → 24 → 20（收窄最大舵量）
                            ③ 还甩 → SIMPLE_KP 14 → 10（降低"每格误差要多少舵"）
                            ④ 补回响应：SIMPLE_LEAD_TICKS 30 → 36
                         先别动 LOST_/CORNER_ 那几项，它们与这个症状无关
     · 弯道里车头转得动、但整条弯贴着探头边缘走（误差一直卡在 3~4 格）→
                          这才是【打舵量不够克服偏航静摩擦】：
                            SIMPLE_KP 14 → 18 → 24，或 SIMPLE_TRIM_KI 150 → 220
     · 丢了线找不回来  → SIMPLE_LOST_SPEED 调小（20 → 16），
                          再加大 SIMPLE_LOST_BOOST（10 → 16）
     · 缓慢的大幅摆动  → 先调小 SIMPLE_TRIM_KI（220 → 150）；
                          还摆再调小 SIMPLE_LEAD_TICKS；最后才调小 SIMPLE_KP
     · ★★ 弯道"明显减速"（直道正常、一进弯整段掉速；屏上第 3 行 B 从 32
       掉到 20 上下，第 4 行 L 出现 0 或很小）→
                          这是【收油收过头】，加大 SIMPLE_CORNER_SLOW_MAX
                          （6 → 8 → 10）。★ 先别动 SIMPLE_CORNER_SLOW
                          （见十三节对策 2b，两个按钮管的事不一样）
     · ⚠ 但若减速的同时第 2 行 LOST 有数 → 那是【丢线回找】，不是收油问题，
       走上面"丢了线找不回来"那一支
  一次只动一个参数，改完立刻跑一圈。
  ★★ 弯道问题有【四种】，药方完全相反，动手前先分清（2026-09-25 / 09-29 实车教训）：
       A. 进弯迟钝 —— 车"没提前反应"（到弯口才发现）        → 加 LEAD_TICKS
       B. 差速过大 —— 车"反应了、但一次打得太猛、往外甩"      → 减 SLEW / DIFF_MAX
       C. 力度不够 —— 车"反应了、力度也温和、却压不回线中间"  → 加 KP / 积分
       D. ★ 弯弯不一致 —— "一个弯内0外60、另一个内15外40"      → 加 LEAD_TICKS
          （2026-09-29 新增。根源是某个弯【车先偏出去】了，误差打到最外侧，
            于是控制器打满舵；是"先偏出去→才打满舵"，不是"打太猛→才偏出去"。
            ⚠ D 和 B 现象很像（都表现为"差速很大"），但药方相反：
              B 要"减舵"，D 要"提前打舵"。区分办法还是看 OLED 的 E 那一行
              —— 误差打到 ±3~±4 就是 D，误差一直在 ±1~±2 但差速很大才是 B。）
     ⚠ 我（手册作者）在 2026-09-25 把 B 错认成了 C：用户说"车头转过来了、
       车身往外滑"，我就断定是"力度不够克服偏航静摩擦"，于是把 Kp 从 8 加到 14
       —— 那正好把 B 治反了。**同一句症状描述可以对应完全相反的病因。**
       用户后来直接点明"力度是够的，是差速过大"，才有了 SIMPLE_DIFF_SLEW。
     B 和 C 的区分办法（不用猜）：看**车偏出去以后能不能被拉回来**。
        能拉回来、只是过程一顿一顿/摆幅大      = B（差速变化太猛）
        拉不回来、一直贴着探头边缘往外蹭      = C（力度不够）
     还可以跑"停在弯里"的测试：看车停稳时探头压在【哪一路】（见第十三节 524 行）。

【⑤ 把"速度换算"量准（可选，但建议做一次）】
  上面"基础速度 42 → 一圈约 17.8 s"是按每 1 PWM ≈ 0.0115 m/s 估算的
  （当前值 32 约 25.2 s，见十四节表 1），你的车肯定不同。
  精确做法：让车只走直线（可以用手扶着不让它转弯），量 1.5 m 用了几秒 t，
           实际速度 = 1.5 ÷ t。目标是 0.31 m/s，对应 t = 4.9 s。
           t 偏大就加 SIMPLE_BASE_SPEED，偏小就减。
  这样调一次，后面所有速度判断都有依据了。

十五、OLED 显示屏（1.3 寸 SH1106 128x64，SPI2）
     2026-09-28 新增
================================================================

【为什么加它 —— 这是本手册里第二重要的一次改动】
  本工程【没有任何串口】（PA9/PA2/PA3 都被电机和探头占了），
  所以在这之前，"误差到底多大、差速下发了多少、有没有被限幅夹住、
  编码器走到哪了"——全部看不见，只能上车跑圈、看现象、反推原因。

  ★ 2026-09-25 那两次误判（把 Kp 从 14 收到 8、又加回 14）就是因为看不到
    内部量。现在这块屏把循迹环里的关键数据摊开显示，调参从"猜"变成"看"。

【接线】OLED 模块（7 针 SPI 版）→ 开发板
      OLED 模块                 STM32F103C8T6          说明
      ─────────────────────────────────────────────────────────────
      GND                    →  GND                   必须共地
      VCC                    →  3.3V                  ★ 别接 5V
      D0 / CLK / SCK         →  PB13                  SPI2_SCK
      D1 / MOSI / SDA        →  PB15                  SPI2_MOSI
      CS                     →  PB12                  片选（低有效）
      DC                     →  PB14                  1=数据 / 0=命令
      RES / RST              →  PA8                   复位（低有效）

  ⚠ 模块丝印有好几种叫法：
       D0/D1  就是  CLK/MOSI；SDA 在很多 SPI 模块上就是 MOSI（不是 I2C 的 SDA）
       有的模块 RES 引脚标 RST，DC 标 A0（A0=0 命令 / A0=1 数据，是同一根）
  ⚠ 一定要买/确认是 **1.3 寸 SH1106**：1.3 寸常见的是 SH1106，
    1.2 寸及以下才是 SSD1306。两者驱动同源但 SH1106 内部 RAM 有 2 列偏移，
    用错驱动会表现为"画面整体右移 2 列"。
    本工程用的是 u8g2_Setup_sh1106_128x64_winstar_f（已经处理好偏移）。

【引脚为什么这么分】
  · SPI1 用不了 —— 默认脚 PA5/PA6/PA7 在本工程全是循迹探头输入；
    SPI1 的重映射版要 PB3/PB4/PB5，又和 IN4 + 两路 PWM 撞死。
    → 只能用 SPI2（SCK=PB13, MOSI=PB15）。
  · SPI2 没有把 MISO 引出来 —— 模式选的是 "Transmit Only Master"，
    只引出 SCK 和 MOSI 两条线，于是 MISO(PB14) 被让出来做 DC 脚。
  · CS/DC/RES 都是普通推挽输出（不是复用功能）。

【屏幕上显示什么】（6 行 × 21 字符，字体 6x10）
  跑的时候（4 行实时量 + 探头 + 里程）：
      RUN  T12.3 L11.8     ← ★ 跑圈计时：T = 这一圈 / L = 上一圈（秒，0.1s）
      E  -2    LOST 0      ← 夹线误差(-4~+4, 99=丢线) / 连续丢线拍数
      B  32    DIFF -12    ← 本拍基础速度(已含弯道收油) / 本拍真正下发的差速
      L  44    R  20       ← 本拍真正下发的左轮 / 右轮 PWM
      [ ][X][X][ ][ ]      ← 五路探头（最左→最右），实心=压到黑线
      ENC  -1605  1224 M2  ← 左右累计计数【单位 = 1000 计数】 + A/B 点进度
                              M0=还没到 B   M1=已过 B   M2=已过 A(一圈跑完)

  ★★ 停车后第 1、2、4 行会【换内容】—— 车一停，E/LOST/B/DIFF/L/R 这些
    "当前值"就恒定不变、没有任何信息量了，让位给"刚跑完这一圈的档案"：
      STOP PL0 TS-1 T 27.1 ← 两个极性标定值 + 刚跑完那一圈的成绩
      BMIN 26/19 LMAX 8    ← ★ 本圈"掉速档案"（2026-09-29 新增，见下）
      EVT  5  MAXW 5       ← 这一圈触发了几次宽线 / 整圈最宽的一拍压了几路
      SLOW@ 543K WIDE@ 867K← 最慢那一拍的位置 / 第一次压宽线的位置(同单位)
      [ ][X][ ][ ][ ]
      ENC  -1605  1224 M0  ← 左右累计计数【单位 = 1000 计数】+ A/B 点进度
    ⚠ 所以"停车后看不到 DIFF/L/R"是正常的，不是坏了。
    ★★ 【不管怎么停的都会保留】：按按键停、双击/三击切极性停、被停止线停，
       这些数都留着 —— 换内容的唯一条件就是"车不在跑"。不需要自动停车。
       (2026-09-29 修: 早先按按键停车会顺手把触发次数清成 0, 屏上永远只剩
        "EVT 0", 标定数据根本读不到。现在统计只在【按启动】时归零。)

  ★★ 单位：第 4、6 行里凡是"里程/计数"都【除以 1000】了（2026-09-29 改）。
     为什么：一圈就有约 140 万个计数，原值一行根本放不下 —— 旧版屏上是
     "ENC-16055181224006 M0"，15 个数字挤成一片、最后一个字符还被挤出屏外。
     现在 4~5 位就够，而且【几个位置可以直接比大小】：
        一圈 ≈ 1414K，B 点 ≈ 345K，C 点 ≈ 707K，D 点 ≈ 1060K
        -> SLOW@ 落在 345~707K = 第一个弯； 1060~1414K = 第二个弯
     ⚠ 标定里程时记得乘回 1000：屏上 -1605 / 1224
        -> (1605+1224)/2 = 1414 -> MILEAGE_LAP_COUNT = 1414000

  ★ 几个数的用法：
      EVT   = 这圈触发了几次宽线事件(0 = 一次都没触发)
      MAXW  = 整圈【最宽的一拍压了几路】→ 它决定 STOP_LINE_MIN_ACTIVE 填几
              (看到 3 就填 3, 看到 5 就填 5；不再靠猜。⚠ 弯道里斜压也会算进去)
      WIDE@ = 第一次触发的里程 → 若它明显小于一圈总计数，说明中途误判了，
              里程门槛要设得比它更大；若≈一圈总计数，那就是真停止线。
      BMIN  = 本圈 base 的最小值，写成 "看见线时/含丢线拍" 两个数：
              26/26  一切正常（弯里 26 ＝ 直道 32 的 81%）
              19/19  收油收狠了、掉到 CORNER_MIN 地板 -> 见第十九节
              26/20  指令值出现过 20 的坑 -> 【丢线】(LOST_SPEED) 才是元凶
              32/32  但车还是真的慢 -> 【指令值没问题】, 去查电池 / 打滑 / 机械
      LMAX  = 本圈最长的连续丢线拍数（0 = 全程一次都没丢过线）
      SLOW@ = 上面那个最小值出现在多少里程 —— 用来判断"是哪个弯最慢"
      ★ 完整的判读表见 safe/track.h 里 Track_GetSlowStats() 的注释。

  停车时第 1 行会换成：
      STOP PL1 TS-1 T12.3  ← 把两个极性标定值亮出来（标定时要盯），
                              后面是刚跑完那一圈的成绩
  如果是【压到停止线自动停下来的】，第 1 行会显示：
      HIT LINE T12.3       ← 明确告诉你"是停止线停的"，
                              这个数字就是这圈成绩（计时跟着自动冻结）
  ★ 为什么运行时不显示极性：6x10 字体一行只有 21 个字符，塞不下"状态 +
    两个极性 + 两个计时"。而极性是"标定值"，跑的时候本来也不用看。

  ★★ 上下留边（2026-09-29）：1.3 寸模块的塑料窗口会盖住最上/最下各约
     3~4 行像素，所以 6 行【不能】从 y=0 排到 y=63，否则"最上面和最下面的
     字各缺小半行"。现在全部行都按 config.h 的两个宏来排：
         OLED_Y0    = 4    第 1 行的 y
         OLED_ROW_H = 9    行距（6 行 × 9 = 54，上下各留 4~5 px）
     ★ 现场如果还看到被切：
         整体偏上/偏下 → 改 OLED_Y0（4 → 5 或 3）
         字太挤/还切   → 改 OLED_ROW_H（9 → 8）
       ❌ 不要把 OLED_ROW_H 加大到 10 以上：6 × 10 = 60，上下就只剩 2 px
          余量，等于绕回原样。

【跑圈计时（2026-09-29 新增，safe/stopwatch.c）】
  目的：H 题要求"一圈 ≤ 20 s"，而本工程没有串口 —— 以前只能拿秒表对着车掐，
        手按的时刻和车真正启动/停止的时刻对不上，一圈能差出零点几秒。
  ★★ 它【不占用任何按键手势】，而是自动跟着循迹开关走：
        短按 PA15 启动  → 计时归零，开始跑（第 1 行出现 RUN T…）
        短按 PA15 停止  → 立刻冻结，那个数就是这一圈的成绩（成为下一圈的 L）
        双击/三击切极性 → 会强制停车，计时跟着停，不会留下一条假成绩
        启动前"探头看不到线"（车根本没动）→ 计时不会开始，不会污染成绩
  ★ 放【两个】数字位的原因：跑第二圈时能直接看到上一圈多少 ——
    判断"我刚改的这个参数到底快了没有"比什么都直观。
  ★ 时间基准用的是 HAL_GetTick()（1 ms），没有额外的定时器：
    这里只要 0.1 s 精度，而 TIM2/TIM3/TIM4 已经分别被编码器和 PWM 占用了。
  ⚠ 显示按 100 ms 刷新（OLED_REFRESH_MS），所以屏幕上的 0.1 s 是"跳"的，
    不是连续的 —— 这是正常的，不代表计时不准。
  ⚠ 计时上限约 10 分钟（STOPWATCH_MAX_MS），到顶就停住不动了。

  ★★ 调"弯道"问题时，盯这两行：
       DIFF   —— 看它【一拍之内跳多少】。实车说"差速过大"，说的就是这个。
                 改 SIMPLE_DIFF_SLEW 后，DIFF 会变成"爬"而不是"跳"。
       L / R  —— 看两侧差多少。差太小就没力气转（静摩擦吃掉了），
                 差太大就是"猛地一拧"。
  ★ 屏幕上能直接做的一件事：把车【停在弯里】，看第五行的方块压在
    最外一两格还是中间 —— 这是第十三节分"根因 A / B / C"的判据。
  ★★ 2026-09-29 加的一条用法：查"两个弯打舵量不一样"时，
     必须同时看 **E（误差）** 和 **DIFF** 两行 ——
        E 打到 ±3~±4、DIFF 顶到 30   = 车先在弯里偏出去了（根因 D，加前视）
        E 只有 ±1~±2、DIFF 却很大    = 才是真的"差速太猛"（根因 B，减舵）
     这两者的药方正好相反。

【CubeMX 里怎么配】（★ 本工程的 TEST1.ioc 已经配好了，一般不用重配；
                        只有要重新 Generate Code 时才需要看这一节）
  1) Pinout & Configuration → Connectivity → SPI2
     · Mode 选 **Transmit Only Master**（这样 MISO 不占引脚）
     · Hardware NSS Signal: **Disable**
  2) SPI2 → Parameter Settings：
       Frame Format          Motorola
       Data Size             8 Bits
       First Bit             MSB First
       Prescaler (Baud Rate) 8        → 36MHz/8 = 4.5 MHz
                                        （花屏/条纹就改成 16 → 2.25 MHz）
       Clock Polarity (CPOL) Low
       Clock Phase (CPHA)    1 Edge
       CRC Calculation       Disabled
       NSS Signal Type       Software
  3) 三根 GPIO（在图上点引脚，右键 → Enter User Label）：
       PA8  →  Output Push Pull / High speed / User Label = OLED_RES
       PB12 →  Output Push Pull / High speed / User Label = OLED_CS
       PB14 →  Output Push Pull / High speed / User Label = OLED_DC
     ⚠ User Label 必须照抄（OLED_RES / OLED_CS / OLED_DC）——
       代码里用的是 OLED_CS_Pin 这种宏，名字对不上就编译不过。
     ⚠ PB12/PB13/PB14/PB15 和 PA8 原本被 CubeMX 自动配成了 Analog
       （"Free pins" 功能干的），配好上面这些它们就自动不再是 Analog 了。
  3b) ★ 2026-09-29 新增：声光提示两根 GPIO（同样右键 → Enter User Label）：
       PB0  →  Output Push Pull / Low speed / User Label = BUZZER
       PC13 →  Output Push Pull / Low speed / User Label = LED
     ⚠ User Label 必须照抄（BUZZER / LED）—— 代码用的是 BUZZER_Pin /
       LED_Pin，名字对不上就编译不过（见 Core/Inc/main.h）。
     ⚠ 初始电平：CubeMX 生成的 gpio.c 会把新脚初置成 RESET（低）。对
       【低电平触发】的蜂鸣器来说那就是"一上电一直响"。本工程在 gpio.c
       里已经手改成 SET，并且 signal.c 的 Signal_Init() 还会再置一次 ——
       所以重新生成代码后即使忘了改 gpio.c，也不会真的响不停。
       （想彻底干净：CubeMX 里把 PB0 的 GPIO output level 设为 High。）
  4) ⚠⚠ **最重要的一条**：CubeMX 一旦执行 "Generate Code"，它会：

【★★★ 重新生成代码后的核对清单】2026-09-28 实测，Generate Code 会丢这些东西
  ① 时钟！！ `Core/Src/main.c` → `SystemClock_Config()` 里
        RCC_OscInitStruct.HSEState
     必须是 **RCC_HSE_ON**。被盖成 RCC_HSE_OFF 的话，PLL 永远锁不上 →
     直接掉进 Error_Handler 死循环 → 开发板"上电什么反应都没有"。
     ★ 根因在 `.ioc`：HSE 是否启用，是看 **PD0-OSC_IN / PD1-OSC_OUT 这两个
       晶振脚还在不在**。如果 `.ioc` 里少了 `Mcu.PinXX=PD0-OSC_IN` 和
       `PD0-OSC_IN.Mode=HSE-External-Oscillator`，CubeMX 就以为 HSE 没启用，
       于是：main.c 写 HSE_OFF、gpio.c 里把 PD0 当空闲脚配成 Analog 并打开
       `__HAL_AFIO_REMAP_PD01_ENABLE()`（把晶振脚抢走）。

十六、停止线自动停车（2026-09-29 新增，同日下午【重做】）
================================================================
【做什么】车压到停止线就【自动断油停车】，不用按键。
          停车同时计时表自动冻结，屏上第 1 行显示 HIT LINE T12.3。

【★★ 为什么重做一遍（这段最重要，别退回旧做法）】
  第一版判据是"连续 3 路同时压黑 + 连续 2 拍"，实车【误判严重】——
  车没跑完就被停住了。根因不是参数没调好，而是那个判据【分不开】：
        循迹黑线，走直       → 压 1~2 路
        循迹黑线，车头一斜   → 线的横向投影变宽 → 压到 3 路  ★ 与停止线重叠
        停止线（5 cm 宽）    → 压 3~4 路
  也就是说"3 路"既可能是停止线，也可能是【弯道里斜着压普通线】。
  而 5 cm 宽的停止线本身最多也就压 3~4 路 —— 所以只看"压了几路"这一个
  维度，门槛设几都分不开（想靠宽度可靠分开，停止线得加宽到 ≥8 cm）。

【现在的判定 = 三个条件【同时】成立】
  ① 里程门槛：车必须已经跑够一定里程，才允许触发      ← ★ 这一条是关键
  ② 宽度：连续 4 路同时压黑（原来 3 路太松）
  ③ 时间：连续 6 拍都成立（= 30 ms，车速 0.26 m/s 约走 8 mm，滤毛刺）
  ★ 为什么①最有用：误判都发生在中途，而停止线只在终点前出现 ——
    一条里程门槛就把前面所有干扰全挡掉了。

【参数（config.h）】
  STOP_LINE_ENABLE      1    压线停车总开关。★ 2026-09-29 已打开
                             0 = 只记录不停车（标定/排障用的观测模式）
  STOP_LINE_MIN_ACTIVE  4    要几路【连续】同时黑（2~5）。实测 MAXW=5
  STOP_LINE_CONFIRM     6    连续几拍都命中才算（6 拍 = 30 ms）
  STOP_LINE_ARM_TICKS   200  启动后多少拍内不检测 = 启动保护
  STOP_LINE_ARM_COUNT   1120000 ★ 里程门槛（编码器平均计数）= 一圈的 80%
                             前提：那条线【在起步点上】。线不在起步点时，
                             压线这个入口会完全不动作（由里程停车兜住），这是有意的。
                             ⚠ 一句话：ARM_COUNT = 线所在的计数 − 一圈的 10~20%
  STOP_MILEAGE_ENABLE   1    ★★ 里程停车总开关（2026-09-29 晚新增）
  STOP_MILEAGE_COUNT    1400000 ★★ 停车里程 = 一圈。到里程就停，与线无关。
                             ★ 想让车停得早一点就调小、晚一点就调大。
                             标尺：一圈 1400000 计数 = 6.142 m → 1 cm ≈ 2300 计数
                             ⚠ 它只影响"停车位置"，不影响 B 点提示（两者独立）

【★★ 现在有【两个】自动停车入口，同时开着、互不干扰】
  入口① 压到停止线（STOP_LINE_*）：需要那条 5 cm 线，把车停在【线的位置】。
  入口② 里程到一圈（STOP_MILEAGE_*）：不需要线，把车停在【起步点】。
  ★ 为什么必须有两个：**压线只能停在"线的位置"**。你那条线在起步点前方
    850K（= 一圈的 61%）处，所以"压线停"会在跑完 61% 圈时就停下，回不到起步点。
    要"从起步点出发、在起步点停止"，参照物只能是【里程】。
  ★ 两个入口的结果会互相印证，屏上第 1 行直接告诉你【是哪个入口停的】：
        HIT LINE T 25.5   ← 压到线停的（线被认出来了）
        LAP DONE T 25.5   ← 里程到一圈停的（线没参与）
  ★ 按 H 题标准做（把 5 cm 线挪到起步点）之后，两个入口会在同一瞬间成立，
    压线那一侧额外提供了"物理位置"这个高精度参照 —— 精度最好。

【★ 怎么把停车点对准（跑完量一次就够，1 cm ≈ 2300 计数）】
  1) 在起步位置的【车轮正下方】贴一条小标记（或就在起跑线上量）。
  2) 启动跑一圈，让它自己停住（屏上出现 LAP DONE / HIT LINE）。
  3) 量"车轮标记"相对"起步标记"差了多少厘米，以及方向：
       · 车【冲过头】了 → STOP_MILEAGE_COUNT 调【小】（每 1 cm 减 2300）
       · 车【没到】     → STOP_MILEAGE_COUNT 调【大】（每 1 cm 加 2300）
     例：冲过头 6 cm → 1400000 − 6×2300 = 1386200
  4) 再跑一圈复核。±2 cm 以内就达到 H 题要求（要求就是 ≤2 cm）。
  ★ 只改 STOP_MILEAGE_COUNT，**不要去改 MILEAGE_LAP_COUNT** ——
    后者同时管着 B 点提示的位置和一整圈的判定，动它会连带一起偏。

【怎么调】
  · 还是误停       → 看屏上第 4 行 WIDE@ 的数：第一次触发发生在多少计数上？
                     把 STOP_LINE_ARM_COUNT 设得比那个数更大
  · 压过停止线不停 → 门槛太大 → 调小；或 MAXW 只有 2~3 → MIN_ACTIVE 调小
                     ★ 也可能是【线不在起步点】→ 那是设计如此（见上面的双入口说明）
  · 一启动就停住   → STOP_LINE_ARM_TICKS 加大（200 → 400）
  · 完全不要这功能 → STOP_LINE_ENABLE / STOP_MILEAGE_ENABLE 改 0
                     （压线那个仍会记录事件，无害）
  · ⚠ 跑动中【不要抬车/别用手挡住探头】：五路全黑会被记成"压到宽线"，
       里程门槛又已经满足的话，车会当场停住（这是有意的，但很容易误以为坏了）。
  · 屏上 EVT/MAXW/WIDE@ 全是 0（跑了整整一圈都没变过）
                   → 先查【编码器计数有没有在走】：第 6 行 ENC 是不是 0/0？
                     是 0 就说明里程根本没在算 —— 见下面的"★★ 编码器坑"。
                     如果 ENC 有数、只有这三个是 0，那是整圈真的没出现过宽线。

【★★ 停车动作与显示】
  · 判定成立 → **立即断油**（`Track_StopDetect` 内部调 `Motor_All_Stop()`），
    并直接改内部模式位停车（**不调 `Track_SetEnabled(0)`** —— 那会清掉标记，
    屏上就看不到 `HIT LINE` 了）。
  · 屏上第 1 行会显示 `HIT LINE T xx.x`，那个时间就是这一圈的成绩（计时自动冻结）。
  · 下次短按启动会把这个标记清掉（几圈就跑几圈，互不干扰）。

【★★ 编码器坑（2026-09-29 修掉的一个致命 bug，务必记住）】
  现象：跑完一圈停下，屏上 ENC 一直是 0/0，WIDE@ 也是 0，A/B 点提示从不响，
        而且把 MILEAGE_LAP_COUNT / STOP_LINE_ARM_COUNT 填好之后
        【停止线永远不会停车】（门槛判断恒为"里程不够"）。
  根因：TIM2/TIM4 只是两个自由计数的硬件计数器。软件要得到"一共走了多少"，
        必须【每拍】读一次硬件计数器、把增量累加进 total。
        早先的写法把"累加"塞在 Encoder_GetDelta() 里，而删掉速度闭环之后
        再也没有任何地方调用 GetDelta() → total 永远停在 0。
  修法：新增 Encoder_Update()（写接口，每拍调一次），Get 全部改成纯读。
        调用点放在 Mileage_Task() 的第一行（它在 CtrlLoop 里，每 5ms 必到）。
  ★ 教训可以推广：**凡是"必须定期被执行"的动作，一定要有一个明确的调用点，
    不能挂在"碰巧会被别人调用"的读接口上。**

【★ 启动保护是干什么的】
  车是【停在启停线上】起步的（H 题 A 点就在起跑线上），没有这一段保护，
  一按启动就会立刻"压到停止线"把自己停住。
  200 拍 × 5 ms = 1.0 s，车速 0.26 m/s 时约等于 26 cm。
  ⚠ 如果你的起跑横线在车前方 30 cm 以内 → STOP_LINE_ARM_TICKS 改 400。

【停车动作】立即断油（Motor_All_Stop），不走"先收油再停"。
  滑行最短（比先收油少滑约 2~3 cm），代价是轮胎有一点点抱死拖滑。
  ★ H 题要"停车偏差 ≤ 2 cm"，这一项只能现场试：若冲过停止线太多，
    说明车速偏高 → 降 SIMPLE_BASE_SPEED。

【代码位置】
  safe/track.c      Track_StopDetect(mask)  判定 + 停车
                    Track_GetStopLine()     给屏上显示用
                    Track_GetWideEvent()    取"触发"统计（次数 / 首次里程 / 宽度）
                    Track_GetWidthMax()     取本圈最宽的一拍压了几路
  safe/mileage.c    里程（里程门槛的数据来源）★ 第一行是 Encoder_Update()
  safe/encoder.c    累计计数 —— 靠 Encoder_Update() 每拍推进，见上面"编码器坑"
  Core/Src/main.c   CtrlLoop() 里在建控制量【之前】调用。顺序很重要：
                    判定成功就直接结束本拍 —— 否则会立刻把刚停住的
                    电机又推起来，车就"停不下来"了。
  ★ 统计（EVT/MAXW/WIDE@）只在【按启动】时归零，停车路径一律不动它们，
    这样按键停、双击三击切极性停、被停止线停，三种情况都读得到数。

【和丢线不会搞混】五路全丢（mask = 0，屏上 E 显示 99）才叫丢线；
  连续 4 路变黑是"看到一大片黑"，两者正好相反，不会互相干扰。

十七、声光提示（蜂鸣器 PB0 + LED PC13）+ 里程 / A·B 点
                                          （2026-09-29 新增）
================================================================
【为什么要有这个】2026 电赛 H 题《车载平衡滚球运动控制系统》要求
  "通过 B 点时声光提示"。赛道（题面）：
        A →B 直线 1.5 m，B→C 半圆 R0.5 m，
        C →D 直线 1.5 m，D→A 半圆 R0.5 m
  一圈 = 2×1.5 + 2×(π×0.5) = 6.142 m，A 点有一条 5 cm 长、垂直于环路的
  启停线（也就是第十六节那个停车点）。

【接线】
  蜂鸣器（有源模块，3 脚 VCC/GND/IO）→ 开发板
        VCC → 3.3V（或 5V，看模块标称）
        GND → GND
        IO  → PB0          ★ 低电平触发（BUZZER_ACTIVE_LEVEL = 0）
  光   → PC13 板载 LED（最小系统板上已经焊好，不用接线）
                          ★ 低电平亮（LED_ACTIVE_LEVEL = 0）
  ⚠ 蜂鸣器电流一般 20~30 mA，PB0 单脚最大约 20 mA。带驱动三极管的
    3 脚模块可以直接接；如果是裸蜂鸣器（两脚/无驱动），要自己加三极管，
    否则会把 IO 拉低甚至带不动。
  ⚠ PB0 是 TIM3_CH3，本工程 TIM3 只用 CH1/CH2（PB4/PB5）做电机 PWM，
    CH3 空闲 —— 所以 PB0 才能当普通 GPIO 用。

【★ A/B 点怎么定的（只标一个数就够）】
  两个点在一圈里的【比例】是固定的，跟轮径、编码器分辨率都无关：
        B 点 = 1.5 / 6.142 = 24.4% 圈
        A 点 = 1 圈（100%）
  所以只要标定【一圈有多少编码器计数】这一个数，A/B 两点自动就出来了。

【参数（config.h）】
  MILEAGE_LAP_COUNT    0    ★ 一圈的编码器平均计数。0 = 未标定（不动作）
  MILEAGE_B_RATIO_PM   244  B 点占一圈的千分比 = 1500/6142（一般不用动）
  BUZZER_ACTIVE_LEVEL  0    0 = 低电平响（有源低电平模块）；1 = 高电平响
  LED_ACTIVE_LEVEL     0    0 = 低电平亮（蓝药丸 PC13）；1 = 高电平亮
  SIGNAL_BEEP_MS       60   短提示音时长
  SIGNAL_LONG_MS       400  长提示音时长

【怎么标定 MILEAGE_LAP_COUNT】
  1) STOP_LINE_ENABLE 保持 0（只记录不停车），MILEAGE_LAP_COUNT 保持 0
  2) 短按 PA15 启动，跑完整整一圈，手动按停（就按 PA15 短按）
  3) 读屏上第 6 行 ENC 的两个数，各乘 1000 再取平均（两边一般只差几个百分点）
     ⚠ 【单位 = 1000 计数】(2026-09-29 起，为了不再溢出屏外)。
       例：屏上 -1605 / 1224 -> (1605+1224)/2 = 1414 -> 填 1414000
     ⚠ 若这两个数一直是 0/0 —— 那不是参数问题，是【编码器累计没在走】，
       先看第十六节的"★★ 编码器坑"（2026-09-29 已修）。
  4) 填进 MILEAGE_LAP_COUNT，重新烧录
  ★ 标定这一圈里【不会】响 —— 因为 MILEAGE_LAP_COUNT 还是 0（未标定 =
    不做任何判定）。这是有意的：宁可什么都不做，也不要拿一个假数乱触发。
    填上数之后，下一圈跑过 B 点就会响。
  ⚠ 换轮子 / 换编码器 / 改了减速比之后必须重新标定。
  ★ 交叉校验：如果第 4 行 WIDE@ 显示的"第一次触发位置"接近你读到的
    一圈总计数，说明那次触发就是终点停止线 —— 两个数是互相吻合的。

【提示方式（两种事件，声和光都不同，不用数次数就能分辨）】
  B 点：短音 1 声（60 ms） + LED 闪 1 下
  A 点：长音 1 声（400 ms） + LED 常亮（下次启动自动熄灭）
  ★ 为什么声光都要：赛场噪声大时可能听不见蜂鸣器；从侧面看不见灯时
    还能靠声音。两个通道一起给，才叫"声光提示"。
  ★ 不用按键 —— 里程一到自动触发。

【屏上怎么看】
  第 6 行末尾多了一个标记：ENC  12345  12005 M2
        M0 = 还没到 B 点    M1 = 已过 B 点    M2 = 已过 A 点（一圈跑完）
  ★ 这个数是给"没注意到声响"时回头核对用的。

【代码位置】
  safe/signal.h .c   蜂鸣器 + LED（非阻塞状态机，不占用控制节拍）
  safe/mileage.h .c  里程 + A/B 点判定（跑在控制中断里）
  Core/Src/main.c    CtrlLoop() 里最先调 Mileage_Task()；
                     主循环里调 Signal_Task()（在 Oled_Task 之前）
  ★ 为什么提示音不用 HAL_Delay 死等：控制环 5 ms 一拍，响 400 ms 就是
    80 拍 —— 死等的话车早就冲出去了。所以只记"还要响多久/几声"，
    由主循环每圈推进一点。
  ★ 中断安全：里程判定跑在中断里，它只把"到过 B/A"记成计数器自增，
    真正的发声/闪灯由主循环做。这样不会出现"提示音偶尔不响"。
    （别改成用 volatile 标志位：中断置位、主循环清零，中间一被打断就会
      把事件吞掉 —— B 点的提示音就永远不响了。）

【引脚占用变化（2026-09-29）】
  PB0  → BUZZER（输出推挽，低速）  ★ 原来是"空闲脚配模拟输入"
  PC13 → LED（输出推挽，低速）     ★ 原来是"空闲脚配模拟输入"
  ⚠ 蜂鸣器是低电平触发的，所以【上电必须是"不响"】。gpio.c 里已经把
    初置电平写成 SET（高 = 不响），而 signal.c 的 Signal_Init() 还会再置
    一次 —— 因为 gpio.c 属于 CubeMX 生成区，重新生成代码会把初始电平改回
    RESET，那样一上电蜂鸣器就会一直响。两道保险就是为这个。

【还没做的】H 题第 4/6 项要求"钢球稳定在摆杆中心"—— 那是摆杆 + 视觉
  那部分。本工程（循迹小车）目前做的是"车"这一半：循迹、计时、停车、
  声光提示、里程。

十九、★ 为什么"跑着跑着明显减速"（2026-09-29 深夜；含掉速档案的用法）
================================================================
【症状】跑完一圈的读数：STOP PL0 TS-1 T 27.1，弯都能转过来，但是
        "进入后面的弯时速度明显往下掉"。

【一、先把"能掉速的地方"数清楚 —— 整个固件里只有 3 处会让 base 变小】
  控制律（safe/track.c）最后给电机的两侧 PWM 是
        左 = base + 差速,   右 = base − 差速
  所以"车变慢"只可能是 base 变小（差速本身不改变平均速度）。而能改动 base 的
  只有下面三条路，一条都不多：

   ① 弯道自动收油（SIMPLE_CORNER_SLOW）
        oil = |差速| × 50%,  base = 32 − oil,  地板 = 32×60% = 19.2
        直道 |差速|≈0~7   -> base 32~29
        弯里 |差速|≈16~32 -> oil 8~16 -> base 24~19   ← ★ 44%~59% 掉在这里
   ② 丢线（SIMPLE_LOST_SPEED）        base = 20   （−37%）
   ③ 从没见过线（SIMPLE_SEARCH_SPEED）base = 12   （只在起步那一段可能）

【二、为什么"弯里"最容易掉到 19 —— 弯道收油的【结构性缺陷】】
  oil 用的是 |差速|，而差速 = Kp×预测误差/2 + 【曲率积分】。
  曲率积分在【持续弯道】里必然顶到自己的上限 16 PWM（它靠"误差持续偏一侧"
  积起来），而它的泄漏条件是 |误差|<=1 —— 弯里误差通常 >1，所以【弯里它不泄漏】。
  于是弯道中后段：|差速| ≥ 16 -> oil ≥ 8 -> base ≤ 24；误差再大一点就压到
  地板 19.2。**"最需要它匀速的时候，它被自己的积分项压到最慢"**。
  ★ 这解释了一个很反直觉的现象："弯都快过不去了，可它偏偏还在减速" ——
    收油本来是安全措施，但被积分项叠加以后变成了"越弯越慢"。
  ★ 也解释了为什么会感觉"是后面的弯在掉速"：油量正比于 |差速|，哪个弯把
    差速用得更满，哪个弯就掉得更狠。而"直道上修正一下"同样会掉速
    （误差 2 格 = 差速 14 -> oil 7 -> base 25），所以屏幕上看不出来"是弯的锅"。

【三、已修 · 现在代码里是什么】
  config.h 新增 SIMPLE_CORNER_SLOW_MAX = 6（收油【绝对上限】）：
        不管差速飙到多少，弯里最多只降 6 PWM  ->  弯里 base 稳定在 26
  仿真（tools/sim_corner_slow.py，轮距 0.27 m、前视 30 拍）：
        无上限：直道 32 | 弯 BC 24/19 | 弯 DA 24/19 | 圈时 27.38 s | 横偏 8.6 mm
        有上限：直道 32 | 弯 BC 26/26 | 弯 DA 26/26 | 圈时 25.21 s | 横偏 5.2 mm
    ★ "最慢的那一瞬间"从 19 → 26（+37%），圈时快 2.2 s，而且横偏反而变小
      （不再被夹到地板上）。两个弯也【被压平】成同一个速度（26/26）。
  ⚠★ 但这份读数（T 27.1）是【加这个上限之前】跑出来的：
      - 27.1 s 与"无上限"的仿真 27.38 s 基本吻合；有上限只有 25.2 s；
      - 这条读数来自加上限之前那一版固件（照片是那一轮拍的）。
    -> 所以第一件事是：【重新编译 + 下载】，然后用同一条赛道再跑一圈对比。

【七、★ 起步点与启停线的关系（决定两个停车入口怎么配）】
  实测：一圈里唯一那条宽黑线（连续 ≥4 路压黑）出现在【61%】处 ——
  862K / 867K / 850K，位置极稳；最宽时压满 5 路（MAXW 5），符合 5 cm 线特征。
  → 你的起步点在它前面（若按 H 题"停在线上起步"，它应出现在 ~100%）。

  ★★ 用户 2026-09-29 晚明确需求："**从起步点出发，在起步点停止**"（起步点不动）。
     这条需求【推翻了"只靠压线停车"的做法】，理由见第十六节"双入口"：
       压线只能停在【线的位置】；线在起步点前方 850K(61%)处，
       所以压线停会在跑完 61% 圈时就停住，**回不到起步点**。
     → 于是新增【里程停车】（STOP_MILEAGE_*）：到一圈（1400000 计数）就停，
       与线无关，因此**不用挪任何东西**就实现了"起步点出发、起步点停止"。
       验证方法：屏上第 1 行会显示 `LAP DONE T xx.x`（里程停的），
       而不是 `HIT LINE T xx.x`（压线停的）。

  ★ 三个配置的对照（记住这张表就不会搞混）：
     ┌───────────────┬────────────────────┬──────────────────┐
     │ 起步点        │ 线在起步点(推荐)   │ 线在前方 850K    │
     ├───────────────┼────────────────────┼──────────────────┤

     │ 谁把车停住    │ 压线(两者同时成立) │ 里程(LAP DONE)   │

     │ 停车点        │ 起步点(=线)        │ 起步点           │
     │ 精度          │ 最好(物理参照)     │ 好(±几 cm，可微调)│
     └───────────────┴────────────────────┴──────────────────┘
     ★ 想让压线也参与进来（H 题那种"线就是 A 点"的做法）：把 5 cm 线挪到
